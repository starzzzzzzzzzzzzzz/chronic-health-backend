# 本地方案工作台

这是用于检查方案生成质量与接口体验的独立 Vue 3 演示页，直接连接当前后端和 MySQL。它使用项目内的虚构患者，真实生成 DeepSeek 候选；不是预填假响应，也不是伙伴前端的替代版本。

## 启动

后端未运行时：

```bash
./scripts/db.sh up
SERVER_PORT=9089 ./scripts/run-demo.sh
```

另一个终端：

```bash
./scripts/run-demo-web.sh
```

打开 <http://127.0.0.1:9090/>。默认选中“晚睡生活习惯”虚构病例（如果该病例存在）。前端首次启动会用锁文件安装依赖；本机验证 Node.js 26.8.2。AI 开关、模型和密钥沿用后端 `.env.ai`，不需要在页面填写。

可用 `DEMO_WEB_PORT=9091 DEMO_API_PORT=9089 ./scripts/run-demo-web.sh` 调整端口。前后端均使用项目脚本；不用修改系统 Java 或旧数据库配置。

## 可以测试的操作

1. 搜索、选择患者，查看 H/F/B/C/E/G 六方面资料及确认状态；缺失项保留未知。
2. 设置名称、日期和补充要求，点击生成。首次会创建方案草稿，再提交后台生成作业。
3. 核对主目标、管理模块、七维纳入状态、建议、事实依据和待补充信息。七维按需纳入，不要求每维都生成内容。
4. 采纳候选后编辑目标、建议标题/内容、纳入状态、后续任务标记和维度原因，再保存到后端。保存不等于送审或发布。
5. 查看历史原始候选，返回当前草稿对照人工修改；也可以输入当前患者的方案版本 ID 打开既有方案。
6. 新建方案会保留之前的后端记录；当前浏览器只记住每位患者最近打开的版本 ID。

已生成候选先保留在作业中，人工采纳后才写入草稿。点击“生成新的候选”会发起一次新的真实 AI 调用。页面不自动重试付费生成；提交结果不确定时保留原幂等键，点击“继续查询此次生成”重放同一请求。查询中断可点“重新查询进度”，刷新后也会读取既有作业。

保存携带当前修订号；冲突会提示并保留页面修改，不自动覆盖。页面切换患者或离开有未保存修改的草稿时会提示。浏览器刷新恢复的是后端已保存内容，不会保存未提交的编辑正文。

## 文件与接口

| 文件 | 职责 |
|---|---|
| `demo-web/src/App.vue` | 患者选择、方案生成、轮询、采纳、编辑、历史查看 |
| `demo-web/src/domain.js` | 展示字典、事实文本、编辑校验与 PATCH 字段投影 |
| `demo-web/src/api.js` | 同源请求、超时与错误处理 |
| `demo-web/src/style.css` | 桌面工作台与窄屏布局 |
| `demo-web/vite.config.mjs` | 仅本地 Vite 服务与后端代理 |
| `demo-web/local-proxy.mjs` | 编辑者凭证读取与代理路径白名单 |

浏览器只请求同源 `/api/*`；本地 Node 代理转换为后端 `/ncd-ai/*`。编辑者 Token 仅由 Node 从 `.env.demo` 读取并加到后端请求，不进入浏览器脚本、存储或 URL。DeepSeek 密钥仍仅由后端使用。浏览器 localStorage 只存患者/版本 ID 和未确认提交的幂等信息，不存患者正文或凭证。

代理只监听 `127.0.0.1`，限定 Host/Origin 和具体编辑路径，拒绝跨站请求；它不提供审核者/患者身份切换。此页使用新 REST 资源，不代表已经补齐伙伴旧版方案与任务接口兼容。

当前 UI 范围止于草稿编辑；条件确认、一审、任务、二审、发布与打卡继续使用已有接口/Apifox。前端构建包需要上述本地代理配合，不能直接作为独立静态生产站点部署。
