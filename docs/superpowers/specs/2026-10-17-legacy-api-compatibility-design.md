# 按前端既有 OpenAPI 适配后端：总体方向与第一批设计

日期：2026-10-17。状态：待设计审阅，尚未实现兼容接口。

## 1. 已确认的目标与依据

用户已确认“按照前端伙伴的来”，以后端适配前端根据旧文档预留的请求为目标，不要求前端先迁移到当前后端新设计的资源路径。旧文档和提供的服务器链接足够启动适配；前端源码不是开始工作的前提。

接口基准为 `http://116.178.155.215:18006/ncd-ai/v3/api-docs`。2026-10-17 获取的定义为 OpenAPI 3.1.0，201 个路径、215 个操作；这些数量包含本次视频核心流程以外的模块，不作为本轮全部交付范围。只读取接口定义，不向旧服务器发送本机凭证或业务写请求。

获取快照保存在本机忽略目录 `.dev/apifox/reference-openapi-current.json`，该文件 SHA-256 为 `29e81e341b7f887a868888ef43c670a6c45fbd8f7af3efe470149e9829ab8f75`。第一批实施时仅将该批必需的契约定义冻结成不含业务数据及凭证的测试夹具，以便独立复现；远端文档随后变化不自动覆盖已确认基线。

用户提供的服务器首页当前是 nginx 默认页，不能据此取得前端页面代码。部分接口响应为动态对象，以及部分通用 schema 名称被多处复用；这些信息不足以证明具体页面如何取值，但不阻挡定义明确的接口适配。

## 2. 技术选择

采用**旧契约适配层**：对外增加前端正在遵循的路径、DTO/VO 和成功响应，内部调用现有业务服务。现有方案、审核、任务、发布、打卡的业务规则和数据库模型继续复用；原有 32 个接口暂时保留，保障已验证流程及逐批迁移。

另两种方式的取舍：直接重命名现有 Controller 和业务对象，会同时影响现有测试及版本语义；要求前端改为当前新接口，违背用户本次已确认的对齐方向。因此不选择这两种方式。

沿用 Java 17、Spring Boot 4.1.1、MyBatis-Plus 3.5.17、MySQL 8.4 和常见 Spring Boot 分层结构，不引入网关、新框架或第二套业务实现。

兼容层负责路由、参数、响应、标识及流程映射，不绕过机构范围、DEMO/REAL 隔离、患者能力、修订校验、禁止自审和幂等规则。旧契约明确成功为 200 的操作，在兼容入口返回 200；内部原有创建接口继续遵循原本的 201 语义。错误使用实际 400/401/403/404/409 等 HTTP 状态，不把失败包装成成功。

## 3. 分批边界

这次适配按可独立验收的子项目推进，各批分别形成明确的请求、响应和测试设计。

| 批次 | 目标 | 结束条件 |
|---|---|---|
| 第一批（本设计的实施范围） | 旧档案列表、稳定档案标识、契约测试基线 | 前端按旧列表请求获得可选择的本机 DEMO 档案；字段、分页、授权和 ID 精度通过验证 |
| 第二批 | 旧患者输入、手工方案提交/编辑及回读入口 | 根据旧接口的输入与候选结构完成真实保存和回读；不能把空草稿伪装为 AI 生成结果 |
| 第三批 | 旧工作流下的两阶段审核、任务生成、排程及发布 | workflowId、候选引用、审核目标、expectedRowVersion 和当前业务版本建立明确绑定，重放与陈旧请求不产生重复结果 |
| 第四批 | 旧患者今日任务与反馈入口 | 正式已发布任务和基础打卡可以按旧请求访问；不把完成计数冒充质量评分 |

旧文档中的报告识别、知识库管理、随访、设备和完整评分等其他子系统不随本次接口适配自动纳入。真实 AI 方案生成仍是未实现能力；先复用已完成的业务，不新增虚假生成进度或伪造医学内容。

第二批之后，旧定义已明确的部分继续按旧契约实现；动态对象中未定义的键，需要通过既有业务文档、受控的演示响应或实际联调补齐。仅对受影响的接口保留未验收状态，不因此暂停其他明确接口，也不宣称整个前端已经零改动通过。

## 4. 第一批对外契约

唯一新增业务操作：

`GET /ncd-ai/store/care/grant-administration/archives`

请求使用原始 `Authorization` Token，无 `Bearer` 前缀；可携带 `X-Request-Id`。不读取前端任意提交的机构、主体或数据模式来决定访问范围。

| 查询参数 | 类型 | 默认值 | 行为 |
|---|---|---|---|
| keyword | String | 空字符串 | 对姓名做字面包含查询，沿用现有 `%`、`_` 转义规则 |
| page | Integer | 1 | 最小 1 |
| pageSize | Integer | 10 | 1 至 100；无效值返回 400，不无限读取数据 |

成功为 HTTP 200，响应包装仍为 `code/message/data`：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "items": [
      {"archiveId": "10001", "name": "虚构演示患者A", "diseaseTags": ""}
    ],
    "total": 1,
    "page": 1,
    "pageSize": 10
  }
}
```

示例编号只说明格式，实际编号取数据库映射。响应不混入当前接口的 `id/size` 等替代字段。`total/page/pageSize` 保持旧定义的数字类型；业务 ID 始终作为字符串输出，包括超出 JavaScript 安全整数范围的 ID。

`name` 使用现有患者姓名。没有结构化疾病标签来源时，`diseaseTags` 返回空字符串，不根据自由文本推断疾病。`age` 仅在有有效且不晚于业务当日的出生日期时返回实际周岁；未知时省略这个旧 schema 未列为必填的字段，不返回虚假年龄或未声明可空的 `null`。年龄计算使用项目 Clock 和 `Asia/Shanghai`，覆盖生日当天的边界。

列表仅显示当前主体有有效 `PATIENT_READ` 授权的同机构、同数据模式 ACTIVE 患者。计数、过滤和稳定排序复用现有患者列表规则；空结果为 items=[]、total=0。

## 5. 档案标识映射

不把 UUID 改成数字、不解析后截断 UUID，也不在每次请求时生成随机 archiveId。

增加独立 `legacy_archive_mapping` 表，通过正整数 BIGINT `archive_id` 映射内部 UUID `patient_id`，并记录 `org_id/created_at`。正整数编号只作为旧接口的不透明标识；并非原远端服务器真实档案 ID，不继承旧服务器任何账号权限。

- `archive_id` 为主键，应用输出十进制字符串；编号不得超过有符号 BIGINT 正数上限。
- `(org_id,patient_id)` 唯一，且以该组合外键指向现有 patient，防止跨机构绑定。
- 解析旧编号后，必须再次验证当前主体、患者机构、数据模式及能力；知道编号不等于获得访问权限。
- Flyway 新迁移为已有患者回填映射；本地 DEMO 初始化在新增虚构患者时同步创建映射，重复启动不改号或重建已撤销授权。
- 保留现有 `external_system/external_archive_id` 的外部来源语义，不占用或覆盖这些字段来保存本机兼容编号。
- GET 列表没有建表、分配编号、创建患者或创建快照的副作用。若新增的患者尚无映射，返回 409 提示映射尚未准备，而不是临时分配编号、静默漏掉患者或返回错误总数。
- 新增映射服务作为以后其他患者写入入口的依赖；以后引入正式患者写入时，须在同一事务调用。尚未建立正式患者新增接口不构成本批的额外开发范围。

## 6. 代码职责

沿用 `com.healthsystem` 分层结构，建议新增 `LegacyArchiveController`、`LegacyArchiveService/impl`、`LegacyArchiveMapping` 实体及 Mapper，以及明确的 `LegacyArchivePageVO/LegacyManagedArchiveVO`。Controller 只处理旧请求和响应，Service 组合现有患者读取、映射和年龄信息，不复制授权 SQL。

SecurityConfiguration 只显式放行这个已认证的 GET 操作，不能用 `/store/**` 通配符开放尚未实现的业务。加入本批对应的 OpenAPI 定义，响应字段按实际可缺省情况声明；不直接导入整份旧规范，使未实现路由出现在“本机已可用”接口组。

迁移和 DEMO 初始化使用现有项目脚本运行。原患者列表、档案摘要、32 个操作及原有 109 项回归基线继续验证；新接口加入后，文档数量断言按新增操作准确更新，不通过删除断言掩盖差异。

## 7. 验证与验收

先写失败测试，再实现最小适配，最后运行完整 `./scripts/test-db.sh -o`，并通过 9089 本机实际 HTTP 请求复核。直接 HTTP、契约校验、Apifox 调试和前端页面联调分别记录，不能互相替代。

第一批必须覆盖：

1. 旧请求参数的默认值、分页、keyword 字面匹配、空结果和越界参数。
2. 响应中的 `pageSize/archiveId`、数字分页类型及 200 成功包装，与冻结的旧 schema 校验一致。
3. 19 位 archiveId 以精确字符串返回，往返解析不经过浮点数；映射重复初始化稳定且不与内部 UUID 混用。
4. 无凭证 401，无授权、过期/撤销授权、其他机构和 REAL 数据不出现在 DEMO 列表；不能自填机构或主体扩大范围。
5. 出生日期缺失/未来日期不生成虚假年龄；生日边界、标签缺失及省略字段满足旧契约。
6. GET 不创建映射、患者、授权或输入快照；缺失映射有明确失败，已有数据不被静默隐藏。
7. 现有接口与完整业务回归通过；原始 DEMO Token 不出现在规范、夹具、截图、日志报告或提交中。

第一批验收只表示旧档案选择入口已兼容，不表示整个方案与任务工作流、真实 AI 或前端所有页面已经兼容。
