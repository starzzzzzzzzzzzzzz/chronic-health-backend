# 七维任务 二审 发布与基础执行设计

日期：2026-10-16。状态：待用户确认本轮具体设计，业务代码尚未开始。

## 1 目标与依据

承接已实现的患者、方案草稿、执行条件和一审，完成“已审方案 → 七维任务组 → 周期排程 → 任务二审 → 发布 → 今日任务 → 打卡与补记”。用户已明确选择确定性规则拆解，暂不接入真实 AI。

本轮仍在 local、显式 DEMO 及虚构资料范围内运行。沿用 Java 17、Spring Boot 4.1.1、MyBatis-Plus、MySQL、Flyway、RESTful 和项目脚本。

需求依据已重新读取原文：

- 《健康管理系统后端业务拆分与开发顺序》任务 T01—T06、二审 S01—S04、发布 F01—F05，以及第九章。
- 《健康管理系统后端开发难点与开发方案》版本、事务、排程和七维边界。
- 《方案到任务AI可读规则与七维任务知识库_整合版V3.0》第 1、4、5、6、11、13 章。
- 《慢病管理补充文档-终版(1)》第 1.3—1.8、2.0、3、8、9 章。
- 项目现有 `DATABASE-DESIGN.md`、`TABLE-DICTIONARY.md`、`PHASE-A-API.md`、`PHASE-B-API.md`。

本地同名的 V3.0(2) 与 V3.0、补充终版(3) 与终版(1) 提取正文的 SHA-256 分别一致，不存在正文版本差异。原始资料和其中示例不提交仓库。

## 2 实施范围与取舍

将本轮分为三个连续、可单独回归的增量，全部交付后才称为本轮闭环完成。

| 增量 | 交付 | 不计为已完成的扩展 |
|---|---|---|
| C | 规则派生、任务组编辑、固定时点排程与轮换、预览、二审、任务包新版本 | 真实 AI、事件锚点接入、未审核医学模板 |
| D | 发布检查与替代预览、幂等事务发布、正式任务详情与按日列表、待通知事件 | 短信、微信或其他外部消息实际送达 |
| E | 一键完成、部分完成、未做、不适中止、实际执行时间、分维度补记、追加更正、结果查询 | 完整七维质量评分、依从性报表、设备、语音图片及预警工单处置 |

本轮任务仅支持 `COMPLETION_ONLY` 评价，明确记录未配置质量评价的原因，质量结果为 `NOT_APPLICABLE`，不生成假分数。这使用补充文档“数据或参数不足时改为计完成”的路径，不宣称实现了固定质量评分模型。增强目标固定为未启用，不因模板示例自动开放增强。

同步规则派生返回 201 和任务包 Location；同步事务发布返回 201，重复请求返回既有资源。暂不建立空转的 AI 作业或假异步进度。以后引入真实模型、异步生成和批量发布时另增作业资源，保留本轮任务包与审核契约。

## 3 方案与任务的来源边界

1. 仅从一审有效且已批准的方案版本生成。保存方案版本、正文修订、正文摘要、一审提交和决策 ID 及一审聚合摘要。不能用其他版本的一审授权当前任务。
2. 从当前版本 `isSelected=true`、`executionGoal=true`、所属维度为 ENABLED 的条目提取候选；非执行说明不强行生成任务。七维代码固定为 medication、diet、exercise、routine、monitoring、tcm、other，不强求七维齐全。
3. 每个任务组保留主目标、方案条目、模块、事实、执行主体和模板版本。一个任务有多个依据时全部保存，不能只留自然语言理由。
4. 任务阶段重新读取最新患者资料并保存独立输入快照，保留与方案快照的变化清单。新增事实进入下周期参考，不自动修改本轮已审目标、禁忌、强度或主体。
5. 确定性生成器读取已审条目和版本化模板，形成可编辑草稿。模板不能提供缺乏依据的处方、医学阈值、运动强度或食物形态。缺少必要执行内容、数量、时点、条件或来源时返回 BLOCKER，不猜值。
6. 固定专业内容和原始来源只读；调整已审医学目标、禁忌、强度、主体等内容必须建立新方案版本并重新一审。任务编辑只开放模板允许的执行编排和普通展示字段。
7. 用药按确认医嘱原样绑定药名、剂量、途径、频次、时点和餐关系，禁止解析自由文本后编造服药时间，禁止轮换或补服建议。医嘱缺乏可信结构化时点时保留草稿问题，不允许发布对应任务。
8. 中医康复仅支持已医学审核入库且由医生确认的穴位模板；本轮不把知识库候选当成已审核模板。缺少有效模板时明确阻断，不能改归“其他”绕过。

开发模板明确标记 DEMO、版本和测试用途，不能被 REAL 访问使用；不把开发夹具标成真实医学审核结果。七维框架及过滤路径均覆盖测试，可发布范围取决于实际具备的已确认内容和模板。

## 4 任务组与排程

任务组表示同一管理目的、维度、执行主体、反馈和安全规则下的重复任务；变体是固定或可轮换内容；预览实例表示某日某执行槽位的一次任务。发布前不创建患者正式任务。

任务组包含来源、标题、动作说明、基本目标、必做或自选、L0—L4 优先级、安全重点标记、执行主体、固定与可编辑参数、反馈模型、停止条件和排程规则。必需属性未确认时不能提交二审。

本轮排程支持：

- 起止日期与业务时区；范围在方案周期内。7、14、28 天均支持，开发上限 90 天；展开最多 5000 实例，超限返回问题，不截断。
- ISO 星期、同日多个具名槽位、固定提醒时点、执行窗口、正常提交截止和补记规则。时间按业务时区展开，数据库时刻使用 UTC；跨日窗口保存独立业务日期。
- 固定内容及饮食、运动的明确候选轮换。默认轮换池 2—5，午餐可配置到 8；相邻执行日不重复。休息间隔来自确认配置；不自行选取文档中存在冲突的抗阻频次或慢跑档位。
- 用药和监测不做多样性轮换；一次服药或一次测量一个独立结果。提醒即使同一时点也不合并药物或不同指标的执行事实。
- 同一执行动作、主体、目标、时点、参数和安全要求完全相同的非药物、非监测重复候选才可去重，并保存全部来源；不能靠相似标题或病种合并。
- L0 安全项不因负担超限删除。按已确认功能分类检查自理每日 10 项、主动录入或拍照 6 项、照护每日 12 项；无法满足则给出阻断和调整建议，不静默删任务。
- ANCHOR 模式在本轮返回明确的不支持问题。没有可信实际事件接入前，不把预计早餐或入睡时点冒充真实事件。

预览保存完整确定的 occurrences、问题清单、规则版本、任务包正文修订与摘要。occurrenceKey 至少区分组、业务日期、槽位和执行序号。同日两个槽位不能被错误去重。重新生成相同输入得到相同顺序和选择；编辑任务正文使旧预览失效。

预览只提供执行编排和数据规则检查，不宣称具备自动医学判断能力。缺少已确认的专业参数或兼容关系直接阻断，而不是判为无冲突。

## 5 二审与版本

任务包状态沿用 DRAFT → IN_REVIEW → APPROVED → PUBLISHED。退回或提交人撤回回到 DRAFT。待审内容不可修改；已批准或已发布内容的任何调整建立新的任务包版本，并重新排程和二审。

复用 review_submission、review_decision 的存储与通用审核资源。新增 TASK 阶段独立业务校验，PLAN 一审现有契约不变。不得把当前只会处理 plan_version_id 的代码直接用于任务。

二审固定任务包内容修订、完整任务组及来源、模板和反馈规则、指定预览 ID、预览摘要及对应一审。提交前再次验证来源、权限、窗口和问题清单；APPROVE 时核对相同目标。内容或预览不匹配返回 409。

审核能力与提交能力分开，沿用禁止自审。两轮可由同一独立审核身份承担，但不能审核自己提交的内容；正式机构角色后续对接。

新方案草稿不改变已发布任务的可见性。旧方案来源能否再生成或新发布，以当前方案版本和有效一审进行检查；已经发布的旧任务只在显式新发布的生效边界被替代。

## 6 发布与每日任务

发布前请求给出任务包 expectedRevision、二审提交 ID、指定预览 ID、effectiveAt 和显式替代范围。先提供只读发布预览，列出将生成、保留和替代的实例，正式发布核对相同摘要。

同一事务锁定患者、来源方案、任务包、审核和发布对象，重新验证两审、模板、来源、范围与预览。严格从二审预览复制正式实例和冻结内容，不在发布时重新生成或读取当前模板拼接内容。

幂等使用机构内 Idempotency-Key 和规范化请求摘要：同键同内容返回原结果；同键不同内容 409；同一任务包不同键也不会产生第二套发布。数据库同时设置任务包发布唯一键和实例 occurrenceKey 唯一键。

同一事务创建 publication、全部 execution_task、outbox_event、版本替代和审计。任一失败全部回滚，不能看见半套任务。通知事件状态与发布状态分开；本轮无真实通道时明确为 NOT_CONFIGURED，不伪造已送达。

新版本只替代显式范围内、到新生效时刻尚未开始且无反馈的旧实例。已开始、已提交和历史任务保留。生效前旧任务不提前消失；到生效边界取消的未来旧任务不计为未完成，也不补造取消期间的历史任务。

列表和详情仅返回同机构、同患者、同数据模式、已发布且满足生效边界的正式实例，重新校验当前授权。不会从 schedule_preview 暴露患者任务。按 executionDate 查询，返回每条任务的 zoneId；未传日期时以配置的业务时区计算今日，默认 Asia/Shanghai。

## 7 基础打卡与补记

患者操作支持 COMPLETED、PARTIAL、NOT_DONE、STOPPED。空的一键打卡请求默认 COMPLETED，表示患者自述完成；不等于系统验证完成量或质量合格。执行时间、数值、原因、体感和补充文字均选填，不能因为没填反馈阻止保存。

服务端独立记录：

- 完成结果：全部、部分、未做、安全中止待核实；全部/部分/未做的完成比例分别为 100/50/0。
- 提交来源：正常提交或事后补记，由服务器接收时刻与发布时固定的截止判断。
- 执行时效：EARLY、ON_TIME、LATE、UNKNOWN，依据患者实际执行时间和执行窗口，不能用提交时间冒充执行时间；实际时间不得晚于当前服务器时间。
- 反馈完整度：完整或反馈较少，依据发布时固定的建议字段；不撤销独立完成事实。
- 质量：NOT_APPLICABLE，本轮没有固定质量评分引擎。
- 安全：未提供信息保持 UNKNOWN；明确异常或 STOPPED 进入 REQUIRES_REVIEW，保留独立待核实事件和提示。后来补交完成反馈不能清除未处置安全事件。本轮不假称已有护士预警工单闭环。

只有已发布、生效、授权且允许提交的任务可打卡；取消或尚未开放任务拒绝。超过正常截止允许按已冻结规则补记实际已经发生的执行，不能提示补做后倒填日期。超过补记截止拒绝普通补记；专业更正另行扩展。

分维度补记使用补充文档第 3.2.2：用药不超过正常截止后 12 小时且早于下一次同药任务开始；饮食、运动、其他至次日结束；作息次日 12:00 正常截止、18:00 补记截止；监测为窗口结束后 12 小时与当日结束的较早者；中医康复窗口结束后 6 小时且不跨执行日。不足以可信确定边界时不开放补记，并展示原因。截止时刻统一为不包含右端的边界，明确测试。

每个任务一个主要反馈，同请求重试通过 Idempotency-Key 收敛。重复主提交不产生第二次执行结果。截止前补充或更正通过追加新反馈版本及 expectedRevision 完成，保留旧值、来源与提交时间；不原地覆盖历史。未完成必做任务保持在应执行任务范围，自选任务单独标识，不纳入依从性或整体质量。

## 8 数据与代码组织

按现有分层新增 TaskGenerationService、TaskBundleService、ScheduleService、TaskReviewService、PlanPublishService、ExecutionTaskService、TaskFeedbackService；校验、来源检查和时钟独立复用。保留 Controller / Service / Mapper，不引入微服务或工作流框架。

新增表分迁移落地：task_template、task_bundle、task_group、task_group_variant、task_group_source、schedule_preview；publication、execution_task、outbox_event；task_feedback、task_result。规则版本先固定到代码与不可变快照，不建设在线规则管理；generation_job 等真实 AI 作业表后续引入。

只增 V5 及之后迁移，V1—V4 不回写。扩展 V4 的 PLAN-only CHECK 为明确的 PLAN/TASK 二选一，补任务包和预览外键、待审唯一约束；原一审数据不变。新表继续带 org_id、复合范围外键和大小写敏感 ID。

写入采用 READ_COMMITTED 和统一锁顺序：patient → care_plan_version → task_bundle → review_submission → publication → execution_task（稳定 ID 顺序）→ feedback/result。取得父锁后重读当前子项。外部通道不在发布事务内调用。

患者端开发身份与编辑、审核身份分开。新增随机本地患者 Token，仅授予指定虚构患者 TASK_READ、TASK_FEEDBACK；编辑身份具 TASK_EDIT、TASK_PUBLISH，审核身份具 TASK_REVIEW；均校验患者和机构范围。普通 staff 不自动具备患者打卡能力。本轮仍不接受 REAL 身份或数据。

所有路径前缀 /ncd-ai；ID 和修订号为 String；沿用统一响应、X-Request-Id 及原始 Authorization。新增接口同步进入 Knife4j。

| PATCH /task-bundles/{id} | expectedRevision 编辑允许字段 |
| POST /task-bundles/{id}/schedule-previews | 生成确定排程预览 |

## 10 验收与交付

先用失败测试锁定各增量，再实现并回归，不只检查正常路径。

1. 已审来源、二次档案快照、七维按需派生、来源可追溯；新档案不改已审目标。
2. 选中说明条目不误生成执行任务；未审核模板、缺主体、医嘱改写或缺时点阻断；DEMO 模板不能用于 REAL。
3. 同日多槽位、跨日、业务时区、7/14/28 天、轮换、固定药物与监测、负担和冲突；相同输入展开稳定。
4. 编辑后旧预览失效，任务二审禁止自审；待审锁定，退回重提、撤回和新版本不复用旧决定。
5. 发布并发、同键重试、键冲突、不同键同包；故障回滚无半套实例，通知失败不回滚发布。
6. 发布前患者不可见，新版生效边界衔接正确，已开始和历史结果不覆盖，权限撤销立即生效。
7. 一键完成不要求可选反馈；完成/部分/未做/安全中止；实际时间未知和按时执行后补记分别保存；七维补记截止边界可控时钟测试。
8. 打卡幂等、并发主要提交、更正历史和修订冲突；补交完成不能抹去既有异常。
9. 全链路越权、跨机构/患者/模式、审计故障与并发锁；保留第一二批及文档访问边界回归。

每个增量提供前端请求/响应和状态约定。最终使用项目脚本运行完整数据库测试、离线构建、9089 HTTP 演示闭环与 Knife4j 浏览器验证，完成独立代码审查。保持 `.env`、`.env.demo` 和来源文件不入库，保留另一项目 worker、flower 容器的停止状态。草稿 PR 分增量提交，不自动合并 main。
