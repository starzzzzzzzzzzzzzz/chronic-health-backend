# 接口提示文案约定

2026-10-20：后端统一将系统提供的用户提示返回为中文。

## 前端如何处理

- 顶层 `message` 用于展示；成功提示为“操作成功”。
- HTTP 状态码、响应 `code`、字段名及枚举值保持不变。`APPROVED`、`BLOCKER`、`ALL_FUTURE` 等仍按原值传输。
- 审核、排程问题继续返回 `code`、`severity`、`fieldPath`、`message`；用 `code` 判断问题类型，用 `fieldPath` 定位表单，用中文 `message` 展示。
- 顶层 `code` 目前主要对应 HTTP 状态，不足以区分所有具体业务错误。本次没有增加细分错误码；不能把中文句子当作稳定协议。
- AI 作业的 `errorCode` 保持原值；`issues.validationErrors` 中由后端校验器产生的已知提示转为中文。
- 用户填写的备注、审核意见、方案内容，以及模型自由生成的内容，不进行全文替换。

前端 `home-care-web/src/utils/messages.ts` 可暂时保留旧英文映射，兼容尚未更新的服务。收到中文提示时直接显示；未知提示保留通用兜底。后端部署更新后，无需再为已覆盖的英文系统提示追加翻译。

## 本次重点覆盖

| 场景 | 中文提示示例 |
|---|---|
| 缺少有效身份凭证 | 请先提供有效的身份凭证 |
| 修改任务包的 groups 不合法 | 任务组列表不符合要求 |
| 缺少执行确认说明 | 请填写执行确认说明 |
| 发布预览失效 | 发布预览已过期，请重新预览并核对任务替换清单 |
| 已有任务需要明确替换范围 | 已有执行任务，请明确设置替换范围为 ALL_FUTURE 后再发布 |
| 自审 | 不能审核自己提交的内容，请由其他审核人员处理 |
| 审核前执行条件未确认 | 必要执行条件缺失、已过期或尚未确认 |
| 排程尚未确认 | 请确认执行日期、时段和允许执行的时间范围 |

涉及方案审核上下文、任务审核上下文、排程预览创建与查询、任务包修改、审核决定、发布，以及其他现有接口的统一响应。

旧排程预览的英文问题提示在读取时转为中文，不改数据库中的旧 JSON 或预览摘要。旧 AI 作业的校验提示也只转换返回副本。

当前仓库及此次核对的远端 `main` 均不存在 `/ncd-ai/demo/reset` 实现。文案目录保留了前端反馈的该提示译文，但这不表示该接口已实现或其返回已验证；若联调环境存在该接口，需要核对部署代码版本。

## 后端维护与验证

中文文案集中在 `src/main/resources/i18n/user-messages-zh-CN.properties`。历史英文文案作为内部查询键用于兼容旧记录，不是前端应依赖的协议。新增系统提示须同步维护文案目录；未识别的提示保留原文，避免用错误翻译掩盖实际问题。

本次在隔离的已跟踪源码副本上叠加修复，运行 8 项基础测试和 42 项数据库接口回归测试，均通过。覆盖中文提示、旧预览摘要不变、来源字段和枚举不变、自审权限，以及审核、排程、发布和兼容接口。隔离副本排除了工作区已有的重复测试类和无关未提交改动。

GitHub 推送与服务器部署是两个独立步骤。服务器更新前，公网接口仍可能返回旧版提示。
