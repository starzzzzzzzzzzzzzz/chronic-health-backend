# AI 方案草稿生成

本轮目标：把 DeepSeek 生成的结构化候选接入现有医生端草稿、一审、任务派生流程。AI 成功返回不等于审核通过，候选采用后仍为 DRAFT。

## 需求依据

| 来源 | 落地要求 |

| 演示视频 714cb995bba7ffe4a56c2f80ff1bd9fc.mp4，V01—V03（本轮复核 00:48、01:40 画面） | 患者选择后的生成状态、病种侧重、七维权重、多病种融合与可编辑建议卡片 |

| 《方案到任务AI可读规则与七维任务知识库_整合版V3.0》1—5 章 | 六方面画像、六类模块、一个周期主目标、七维按需启用、事实来源追溯；未知不能补成事实 |
| 同上 6.1、11.1 | 用药零改动，中医须已审核模板；当前草稿层尚无专业参数绑定能力，AI 将相关维度留待确认或关闭 |

视频权重是可编辑候选信息，不能当成已验证的医学公式。现阶段不编造主次亚型、优先级字典或参考文献。

## 运行方式

使用 `.env.ai.example` 作为空模板。配置保存在 Git 忽略的 `.env.ai`：`DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL=https://api.deepseek.com`、`DEEPSEEK_MODEL=deepseek-flash`、`HEALTH_AI_ENABLED=true`。项目 `scripts/run.sh` 自动加载；未开启时仍可使用原人工流程。

```bash
SERVER_PORT=9089 ./scripts/run-demo.sh -o
```

服务端只允许 DEMO 数据生成。本版本不会向供应商传输患者姓名、患者主键或联系方式字段；发送白名单投影后的事实内容、来源类别、确认状态、时间、缺失和冲突信息。自由文本仍可能含身份信息，因此此限制不能称为通用脱敏方案，真实数据接入另行设计。

使用 JDK HttpClient 调用官方 Chat Completions，JSON 输出、关闭 thinking、temperature=0.2、输出最多8000 tokens，90秒请求超时；这不是临床参数。可重现所需的输入、系统提示词、规则版本、请求模型、供应商返回模型标识（usage.providerModel）、模型返回及用量在生成记录中保留。密钥不写日志或数据库，不在前端传递。

## API

均省略 `/ncd-ai`，沿用原始 `Authorization` DEMO Token。

| 方法和路径 | 请求/行为 |
| --- | --- |
| `POST /plan-versions/{id}/generation-jobs` | `expectedRevision`、`expectedProfileRevision`（字符串），可选 `retryOfJobId`；要求 `Idempotency-Key`；202 + Location |
| `GET /plan-generation-jobs/{id}` | 状态、输入快照ID、模型/规则版本、candidate、issues、usage；不返回原始模型文本和系统提示词 |
| `GET /plan-versions/{id}/generation-jobs` | 最近20条生成历史 |
| `POST /plan-generation-jobs/{id}/adoptions` | `expectedRevision`；采用候选，200 返回现有 CarePlanDraftVO |

前端步骤：选择患者 → 按已有接口创建草稿（或打开草稿）→ 保存补充要求 → 创建生成作业 → 轮询 → 展示候选和待确认问题 → 采用 → 原草稿编辑与一审。

这些是新增 RESTful 资源，尚未实现旧 `/store/care/coordination/workflows` 的完整兼容入口，不能宣称前端仅改地址即可接入全部流程。

## 一致性和失败处理

- PENDING → RUNNING → SUCCEEDED / REJECTED / FAILED；采用后 APPLIED。只显示真实状态，不估算虚假百分比。
- 同一幂等键重试返回同一记录，不重复计费；相同键不同请求返回409。每个草稿最多一个活动作业，当前组织最多20个排队/运行作业。
- 后台逐个认领作业，在数据库事务之外调用模型；调用前再检查患者授权。
- 校验未知字段、七维完整决策、模块/事实引用、已确认诊断来源、权重合计、专业字段和参考来源约束，复用现有草稿结构校验。
- 模块的事实索引由模型声明与条目 basis 的明确关联取并集；只汇总输入快照已有事实和已选模块，补齐项记录在 issues.normalizations。未知事实、未选模块或重复依据仍拒绝，不推断或新造依据。原始输出保持不变。
- 自然语言的医学正确性无法通过这些结构校验保证，仍需人工核对；SUCCEEDED 不表示医学正确或可自动发布。
- 生成不修改现有草稿；采用原子更新快照、完整候选内容、修订和审计。采用后保留原生成记录。生成后若有人编辑过草稿，返回409，不覆盖手工修改。
- 提供明确的待确认和缺失信息；相关 PENDING 维度沿用一审阻断规则。模型不自动批准方案，也不自动发布任务。
- 超时、鉴权失败、余额不足、限流、截断、非法输出分别返回安全错误码；不记录供应商原始错误正文。进程中断遗留 RUNNING 超过5分钟标为失败，不自动再次调用付费接口。人工重试创建新记录，冻结当时最新输入。规则升级后未执行的旧规则队列返回 AI_RULE_VERSION_CHANGED，避免用新校验规则冒充旧版本记录。
- 生成后档案变化不自动修改候选；带有人工侧重确认的候选，在采用前再次检查来源摘要，过期则409并要求重新评估。后续任务生成继续遵循原有下次方案参考规则。

## 本轮边界

当前 AI 负责方案层，任务生成继续使用已验证的确定性规则。一审、二审、发布及打卡规则保持原流程。药物与中医专业参数库、文献检索与来源核验、七维完整质量评分、真实身份与真实患者接入不在本轮实现范围。

模型规则文件：`src/main/resources/ai/plan-system-v5.txt`。这是一份版本化的业务规则摘要，并非完整专业知识库，也不是已经完成医学审核的临床内容库。
