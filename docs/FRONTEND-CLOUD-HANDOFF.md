## 凭证与请求

三个独立虚构 DEMO 身份：编辑者、审核者、患者。凭证由后端负责人单独提供；不写入公共仓库、共享文档或公开演示包。当前不是正式登录系统，身份只用于测试虚构记录。

```http
GET /ncd-ai/patients?page=1&size=20 HTTP/1.1
Host: 120.26.14.242
Authorization: <编辑者原始 Token>
```

Token **不加 Bearer 前缀**。一审、二审决策使用审核 Token；打卡、更正使用患者 Token。写接口按文档传递 `expectedRevision`，发布、打卡、AI 生成等接口按文档携带 `Idempotency-Key`，重试时保持相同请求和相同键。

Apifox：导入上面的 OpenAPI 数据源，新建“云端联调”环境，把前置 URL 设置为 API 基址；Token 仅填本地值。先测健康检查，再用编辑 Token 查询患者。

## 浏览器跨域

当前白名单：

- `http://116.178.155.215:18006`（按伙伴此前提供的地址配置，实际地址变化时需要调整）
- `http://localhost:5173` / `http://127.0.0.1:5173`
- 本地 9090、3000、8080 端口的上述两个主机
- API 自身的 HTTPS Origin

页面 Origin 要包含完整的协议、主机和端口；其他 Origin 会返回 403。允许 Authorization、Content-Type、Idempotency-Key、X-Request-Id 请求头。没有使用跨站 Cookie，不需要 `credentials: include`。

## 建议联调顺序

1. 健康检查 → 患者列表 → 六方面资料。
2. 创建方案草稿 → AI 生成作业 → 查询进度 → 人工采用 → 编辑保存。
3. 执行条件确认 → 一审 → 从方案派生七维任务结构。
4. 排程确认 → 二审 → 发布 → 今日任务 → 打卡、更正。

已有前端的旧契约适配边界见 [前端契约对齐](FRONTEND-CONTRACT-ALIGNMENT.md)。服务器部署不等于旧接口已全部适配：请以当前 OpenAPI 和适配说明中的已实现接口为准；发现路径或字段差异时记录具体请求与响应，再逐项对齐。

## 已验证与限制

公网 HTTPS 下完整虚构业务闭环 34 次请求通过；另有 8 项网关验证通过，覆盖预检、允许/拒绝 Origin、鉴权、文档、隐藏 Actuator。验证期间未使用 SSH 隧道。真实 AI 生成和采用已在同一云后端通过 SSH 隧道验收。

当前只是开发联调环境：使用虚构资料、固定 DEMO 身份；不录入真实患者数据。用药和中医缺少专业来源时保持关闭。AI 只生成候选，不自动审批。未进行并发压力测试；网关限流时返回 429，暂停后重试，避免同时批量生成。

前端页面尚未共同联调验收。开始接入后，优先确认“患者选择→资料展示→生成候选→保存草稿”这条主线。
